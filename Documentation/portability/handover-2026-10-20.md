## First task next time: empty notification windows

Both genuine Guider and Sequencer now reach NINA's notification host. Its original
`NotificationManager.EnsureHostWindow` calls `Show(); Hide();` before adding an
item. The transparent, borderless SizeToContent window initially desires zero.
`NativeWindowPeer.ToPixels` currently rejects zero or less than one physical
pixel. This is a WPF backend boundary, not an image-processing failure.

Independent architecture, simplicity and verification perspectives recommend:

- Accept valid finite nonnegative extents and allocate at least one native pixel.
  Retain invalid input, checked conversion and X11 upper-bound rejection.
- Preserve existing zero-sized managed peers. Extend the size acknowledgement
  matcher to recognize the native one-pixel allocation for requested zero while
  retaining existing floor/ceiling matches. A backend-only clamp can leave a
  resize pending and cause repeated layout requests.
- Normalize finite zero/subpixel maximum constraints too. Native zero currently
  means unbounded; reserve that sentinel for positive infinity.
- Keep native metrics truthful. Do not add a synthetic logical-geometry layer,
  public API or NINA workaround for this repair.

These are recommendations, not implemented or qualified changes. Start with a
small explicit checklist and tests in the existing fixtures. Preserve the current
Guider/Sequencer causal reds. Extend the existing deferred acknowledgement test
and replace the native fixture's old zero/subpixel rejection expectation. Cover
both axes, grow/shrink around one physical pixel, empty Show/Hide then content
add/remove, repeated layout settlement, constraints and later recovery at 96 and
fractional DPI. Existing managed zero-client behavior must remain valid.

Use the existing WindowLifecycle StockOracle for a focused nonactivating Windows
calibration branch, skipping its activating default cases. No StockOracle edit,
build or calibration was completed. Do not guess stock ActualWidth/Height or
require empty ContentRendered. No new harness or dependency is needed.
