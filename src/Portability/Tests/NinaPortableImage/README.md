# Portable NINA.Image component

`eng/portability/Build-NinaPortableImage.ps1` builds the complete pinned NINA.Image source at revision `4742afae0a09c79be772f23fcf163fb5852d2775`. The 74-file manifest includes the original image directory, common assembly identity, build properties and MPL license. Inputs remain unchanged. The builder copies sources into a new owned output, applies nine enumerated source adaptations and adds one internal allocation owner. It generates an offline net10.0 project using the existing stock dependency closure and a complete hash-verified WPF runtime family. No new package, native shim or framework API is introduced.

The original assembly identity, public members and empty manifest-resource inventory remain intact. Windows retains its existing GDI paths. Linux uses existing Accord kernels through borrowed views of independently owned memory. The buffer owner allocates and releases memory once, initializes padding and provides a fresh borrowed view for each call because the original NoBlurCanny implementation disposes its source wrapper. Allocation, cloning and copy wrappers that request `ntdll.dll` are avoided. Gray8 rows retain canonical four-byte alignment. Gray16 and Rgb48 rows are packed for remapping.

The original Windows remapping kernel ignores row padding. With odd image widths it remaps padding as samples and leaves some real samples unchanged. The accepted Linux behavior processes every real sample and keeps raw scientific arrays unchanged. This intentional difference applies to Gray16 and linked/unlinked Rgb48 stretch. Even-width stock reference outputs remain exact, including color channel order, debayer arrays, grayscale coefficients, ushort truncation and high-byte conversion.

Default Canny is the original GaussianBlur with sigma 1.4 and size 5 followed by the unchanged NINA NoBlurCanny with thresholds 10/80. The destination starts with original input pixels, matching the original in-place Canny hysteresis boundary behavior. The independent Windows calibration is retained under `current/nina/canny-composition-probe-1`: 38 pixel cases, constructor defaults and zero mismatches. The production component tests exercise the entire real Stretch/Detect path with all five noise modes and resize. Measurement arithmetic remains in the original shared StarDetection methods.

Annotation uses ordinary WPF DrawingVisual, DrawingContext, FormattedText and RenderTargetBitmap. Original geometry, brightest-star limits, labels, ROI conditions and cancellation remain. The result is frozen Bgr24 at original dimensions and 96 DPI. Background pixels use exact original grayscale coefficients and `sample >> 8`. Linux font fallback and WPF antialiasing differ from Windows GDI rasterization; these display pixels are not scientific sample values. Annotation tests require actual colored geometry and label pixels without claiming GDI font pixel identity.

The builder emits `image-consumer-intake.json`, DLL/PDB hashes, the matching PE/PDB identity, every physical or embedded generated PDB source checksum and the adapted source manifest. It preserves wrapper inputs inside its output so an intermediate intake remains immutable during later work. Its intake establishes source provenance and build success. Behavior results are separate. Neither component build nor focused tests qualify a full application launch or camera acquisition.

## Focused qualification

Build `Qualification.csproj` with the existing SDK 10.0.401, isolated output/intermediate directories, no package sources and `ImportDirectoryBuildProps=false` plus `ImportDirectoryBuildTargets=false`. Supply `OriginalManagedDirectory`, `NinaImagePath`, `NinaCorePath` and `FrameworkRuntimeDirectory`. For the Windows reference add `ImageProfile=stock`; this selects the existing WindowsDesktop WPF runtime. Linux uses the owned framework and one copied WindowsBase contract in the test dependency graph, avoiding the .NET facade.

Run with five arguments: report path, Image DLL, Core DLL, original managed directory and framework directory. This executes five annotation checks. For scientific qualification append `science-reference` and a new reference directory on Windows using the original Image/Core pair. This records raw sensor fixtures once, exact stretched pixel arrays, measured results, debayer arrays and exported public contracts. Append `science-compare` with that immutable directory on Linux using the adapted Image/Core pair. Only CRLF/LF differences in JSON formatting are normalized. Numerical values and raw pixels are compared exactly. The two original analytic Gaussian measurement tests retain their existing tolerances.

Linux annotation drawing needs the existing stage's `runtimes/linux-x64/native` directory on `LD_LIBRARY_PATH` for its pinned Skia and HarfBuzz assets. No display server, vendor driver, simulator inventory or application replacement is used by these component tests. The real ImageControlVM preparation and visible original MainWindow remain separate integration checks.

## CFITSIO boundary

CFITSIO is NINA's existing FITS dependency. The Linux profile uses the exact upstream 4.7.0 commit `d6d27653740864a0483e74cff23c53e34e1dceee`, built on the qualified Ubuntu 22.04/glibc 2.35 VM with `--without-fortran --enable-reentrant --disable-curl --without-bzip2 --enable-shared --disable-static`. Native feasibility evidence and complete release notices are retained separately under `current/nina/cfitsio-intake-20261021-1` and `current/nina/cfitsio-feasibility-20261021-1`. This is an existing dependency adaptation, not a replacement FITS algorithm.

The Image builder requires `CfitsioLibraryPath`, `ExpectedCfitsioLibrarySha256` and `CfitsioNoticesDirectory`. It preserves the verified runtime file as `native/External/x64/Cfitsio/libcfitsio.so.10`, copies its exact notices and records both in `image-consumer-intake.json`. The qualified library SHA-256 is `4558BDC93601DAB4ADCA9FB36502198BC98C926BA9BB7038A417E6A4E17420E8`. It depends on libc, libm and system zlib. No install or global loader configuration is required.

Only NINA.Image's CFITSIO initializer registers the exact assembly resolver on Linux and bypasses its original Windows preload. Other imports are left to their existing resolution. The resolver loads only `External/x64/Cfitsio/libcfitsio.so.10` below `AppContext.BaseDirectory` on Linux x64. Qualification records the actual loaded module path and hash. Windows keeps the original preload and import declarations.

Public signatures remain unchanged. Private Linux calls use `ffgpxvll` for 64-bit pixel coordinates, `ffcrimll` for axes and `ffgkyjj` for integer keys. `ffomem` receives its `size_t` delta argument by value. Existing `ffppr` and `ffukyj` 64-bit scalar arguments retain their widths. Pixel reads query the actual axis count before native access. The original helper fills trailing coordinates with 1 for first-plane imports while direct calls with undersized coordinate vectors fail explicitly. The unused original output-only `fits_get_img_size` declaration is explicitly unsupported on Linux because it cannot safely provide an axis buffer. No general ABI translation layer is introduced.

Linux construction and load failures close owned handles and compressed temporary outputs with fresh status values. A pointer is cleared after close or free so later cleanup cannot reuse it. Writer buffer sizes and datatypes are checked before native sample access. Cleanup never deletes an existing destination; its sentinel bytes and SHA-256 are checked after a rejected creation. The original scientific conversion loops, metadata parsing, row order and Windows behavior remain.

Append `fits` and a fresh work directory to the existing qualification arguments for the ushort profile. Tests cover the default managed legacy save followed by original load, the alternate NONE writer, odd-width 17x3 lossless RICE with `.fits.fz` on and off, first/middle/last rows, row bounds, low bytes and endpoints, exact metadata, source preservation, malformed/truncated/missing inputs, exception cleanup and two independent concurrent files. Compressed file bytes are not treated as an interoperability oracle; decoded samples are exact. Append `fits-legacy-reference` on original Windows and `fits-legacy-compare` on a candidate to compare deterministic default legacy bytes with fixed metadata, without loading CFITSIO.

This first slice qualifies ushort data with NONE/RICE and focused normalized FLOAT_IMG/DOUBLE_IMG import vectors. The floating cases use independently specified ushort results for `[0, 1/65535, 1/4, 1/2, 32768/65535, 1]`: `[0, 1, 16383, 32767, 32768, 65535]`. They exercise original `FITS.Load` and reader conversions without invoking the unsafe float constructor. The float fixture is written with the existing typed native API and matching `TFLOAT` datatype. Values outside the declared normalized interval are not assigned a new policy. The remaining FITS ledger is explicit:

- NINA's selected `FlatArrayInt` writer and its original signed-int import normalization still need focused qualification.
- Float and double import conversion loops are unchanged. The focused normalized vectors are qualified separately from wider FileSkySurvey image/content cases and the actual UI path.
- The unused `float[]` writer constructor originally passes `TDOUBLE`. For `[1f, 0f]`, that requests 16 input bytes from an 8-byte array. Linux rejects the datatype mismatch before the native write and closes its newly created handle. This slice neither runs the unsafe Windows operation nor changes its numerical semantics.
- Original byte and Int64 imports that reach a missing datatype mapping retain explicit rejection. No mapping or new normalization policy is invented.
- A distinct-plane 2x2x2 ushort fixture qualifies the original `FITS.Load` first-plane behavior with unchanged file bytes and source samples. The lower-level undersized-coordinate guard is checked before native access. Broader color/higher-axis imports, other compression modes and the original unused image-size API remain outside this qualification profile. The reader's existing higher-axis rejection is unchanged.
- No retained actual Windows CFITSIO DLL is available for native Windows FITS roundtrips in this slice. The Windows scientific/public-contract and deterministic managed legacy-write regressions are separate from that gap.

Component qualification does not establish a full application workflow, acquisition, publication or a final completion claim for all FITS import paths.
