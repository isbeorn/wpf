# Portable NINA.Image component

`eng/portability/Build-NinaPortableImage.ps1` builds the complete pinned NINA.Image source at revision `4742afae0a09c79be772f23fcf163fb5852d2775`. The 74-file manifest includes the original image directory, common assembly identity, build properties and MPL license. Inputs remain unchanged. The builder copies sources into a new owned output, applies five enumerated source adaptations and adds one internal allocation owner. It generates an offline net10.0 project using the existing stock dependency closure and a complete hash-verified WPF runtime family. No new package, native shim or framework API is introduced.

The original assembly identity, public members and empty manifest-resource inventory remain intact. Windows retains its existing GDI paths. Linux uses existing Accord kernels through borrowed views of independently owned memory. The buffer owner allocates and releases memory once, initializes padding and provides a fresh borrowed view for each call because the original NoBlurCanny implementation disposes its source wrapper. Allocation, cloning and copy wrappers that request `ntdll.dll` are avoided. Gray8 rows retain canonical four-byte alignment. Gray16 and Rgb48 rows are packed for remapping.

The original Windows remapping kernel ignores row padding. With odd image widths it remaps padding as samples and leaves some real samples unchanged. The accepted Linux behavior processes every real sample and keeps raw scientific arrays unchanged. This intentional difference applies to Gray16 and linked/unlinked Rgb48 stretch. Even-width stock reference outputs remain exact, including color channel order, debayer arrays, grayscale coefficients, ushort truncation and high-byte conversion.

Default Canny is the original GaussianBlur with sigma 1.4 and size 5 followed by the unchanged NINA NoBlurCanny with thresholds 10/80. The destination starts with original input pixels, matching the original in-place Canny hysteresis boundary behavior. The independent Windows calibration is retained under `current/nina/canny-composition-probe-1`: 38 pixel cases, constructor defaults and zero mismatches. The production component tests exercise the entire real Stretch/Detect path with all five noise modes and resize. Measurement arithmetic remains in the original shared StarDetection methods.

Annotation uses ordinary WPF DrawingVisual, DrawingContext, FormattedText and RenderTargetBitmap. Original geometry, brightest-star limits, labels, ROI conditions and cancellation remain. The result is frozen Bgr24 at original dimensions and 96 DPI. Background pixels use exact original grayscale coefficients and `sample >> 8`. Linux font fallback and WPF antialiasing differ from Windows GDI rasterization; these display pixels are not scientific sample values. Annotation tests require actual colored geometry and label pixels without claiming GDI font pixel identity.

The builder emits `image-consumer-intake.json`, DLL/PDB hashes, the matching PE/PDB identity, every physical or embedded generated PDB source checksum and the adapted source manifest. It preserves wrapper inputs inside its output so an intermediate intake remains immutable during later work. Its intake establishes source provenance and build success. Behavior results are separate. Neither component build nor focused tests qualify a full application launch or camera acquisition.

## Focused qualification

Build `Qualification.csproj` with the existing SDK 10.0.401, isolated output/intermediate directories, no package sources and `ImportDirectoryBuildProps=false` plus `ImportDirectoryBuildTargets=false`. Supply `OriginalManagedDirectory`, `NinaImagePath`, `NinaCorePath` and `FrameworkRuntimeDirectory`. For the Windows reference add `ImageProfile=stock`; this selects the existing WindowsDesktop WPF runtime. Linux uses the owned framework and one copied WindowsBase contract in the test dependency graph, avoiding the .NET facade.

Run with five arguments: report path, Image DLL, Core DLL, original managed directory and framework directory. This executes five annotation checks. For scientific qualification append `science-reference` and a new reference directory on Windows using the original Image/Core pair. This records raw sensor fixtures once, exact stretched pixel arrays, measured results, debayer arrays and exported public contracts. Append `science-compare` with that immutable directory on Linux using the adapted Image/Core pair. Only CRLF/LF differences in JSON formatting are normalized. Numerical values and raw pixels are compared exactly. The two original analytic Gaussian measurement tests retain their existing tolerances.

Linux annotation drawing needs the existing stage's `runtimes/linux-x64/native` directory on `LD_LIBRARY_PATH` for its pinned Skia and HarfBuzz assets. No display server, vendor driver, simulator inventory or application replacement is used by these component tests. The real ImageControlVM preparation and visible original MainWindow remain separate integration checks.
