# Retained rendering integration

This executable uses the actual portable fork's `DrawingVisual.RenderOpen`, `UIElement` layout and `OnRender`, retained `RenderData`, `DrawingContextWalker`, visual tree and dispatcher `MediaContext`. The CPU target and walker are compiled inside the source-built `PresentationCore`, not linked into this fixture. Reflection accesses the internal target without adding a public WPF API for testing.

From `src/Portability`, build the complete reference graph and run:

```powershell
dotnet build Tests/RenderingIntegration/RenderingIntegration.csproj --artifacts-path ../../artifacts/portability/rendering-integration -p:RestorePackagesPath=E:/Projects/wpf/artifacts/portability/packages/ -p:NuGetAudit=false
dotnet ../../artifacts/portability/rendering-integration/bin/RenderingIntegration/debug/RenderingIntegration.dll
```

For Linux, use the installed Linux SDK under `artifacts/portability/dotnet-linux-x64`, the Linux package cache and a separate artifacts directory. The fixture selects Arial from the Windows fonts directory or `/usr/share/fonts/truetype/dejavu/DejaVuSans.ttf` on Linux. A missing font fails the glyph check rather than silently skipping it.

The output is JSON and failures return exit code 1. Each check runs on an isolated dispatcher thread with a 15-second watchdog.

The behavior checklist covers:

- Actual recorded clipped and transformed rectangles with composite opacity.
- Rounded rectangle radii clamped independently on each axis, through both retained geometry and the direct drawing command.
- A real outlined Boolean union preserving the source geometry's retained pixels.
- Genuine rectangle-command and cubic-geometry content bounds before and after retained rendering, including transform mutation and corresponding changed pixels.
- Real `UIElement.Measure`/`Arrange`, retained `OnRender` pixels, brush invalidation and `InvalidateVisual`/`UpdateLayout` recording.
- Actual opacity `AnimationClock` progression in both directions, observed at Background priority through intermediate clock progress, property values and raster alpha, followed by held endpoints and clock removal restoring the base value and pixels.
- Brush and transform mutation repainting without another `RenderOpen`, including restoring values.
- Content replacement removing subscriptions to the original resources, checked through actual dispatcher render postings.
- Visual child order, offset, clip, opacity, addition and removal.
- `DrawingGroup`, ellipse, pen and transformed `StreamGeometry` traversal, including zero-width strokes and overlapping opacity layers.
- Actual `GlyphRun` indices, advance widths, offsets and baseline placement, plus retained foreground brush mutation and physical DPI scaling.
- Surface growth, shrinking, expose invalidation, invalid dimensions, thread affinity and repeated close/reopen with pending work.
- Independent X/Y DPI changes, 1x/2x/1x round trips, physical surface bounds and preservation of the previous surface/scale after invalid inputs or failed allocation.
- Successful-frame notifications after canvas restoration, including callbacks that mutate content, reenter rendering, dispose the target or throw, plus absent notifications after failed frames or disposal.
- Explicit failure for an unsupported opacity mask and successful rendering afterward with canvas state restored.

This establishes a bounded retained CPU rendering slice. It does not establish `PresentationFramework` view rendering, native window presentation, text shaping coverage, native input, automatic monitor DPI detection, arbitrary brushes, image/video rendering, effects, arbitrary dashed-pen profiles, right-to-left text or full WPF/NINA compatibility. Unsupported drawing operations throw a named `NotSupportedException`; they are not silently omitted.

The animation regressions failed against the previous source: each Background observer ran only at the endpoint, missing all intermediate values and pixels. The portable render loop now consumes invalidations generated by its timing tick in the upcoming frame while retaining pending requests from earlier iterations and later callbacks or drawing. The tests pass by observing the actual intermediate clock, property and raster together, not by asserting a frame-count threshold or promoting the observer's priority. The existing completed-frame mutation, reentry, exception and disposal checks remain in the same suite.

On 2026-10-18, isolated SDK 10.0.401 Windows and Linux builds returned zero warnings and zero errors, with all 19 renderer cases passing. The source lifecycle suite passed 29 cases on both systems. The separate Core regression retains its two-pass user `Rendering` mutation check. Red results, build logs, the unchanged diagnostic probe's before/after clock and pixel traces and source/binary hashes are under `artifacts/portability/animation-investigation`. These source builds do not replace the preserved final2 packages or their original failing native workflow evidence.

Retained visibility checks are shared with the existing stock guideline oracle through VisibilityCases.cs. Run this fixture with --visibility-only for the focused corpus. Hidden/Collapsed UIElements and zero-opacity raw visuals must skip all retained content and descendants, including unsupported brush/effect/mask commands. Unattached visible roots still paint, opacity and visibility round trips restore pixels and skipped guideline/scaling/recursive-brush state leaves siblings intact. Dispatcher-driven VisualBrush checks distinguish a skipped consumer, whose off-tree source dependency must be removed, from a directly sampled invisible source, whose dependency must remain to observe visibility recovery.

The bounded dashed-painting regression retains one actual Pen/DashStyle and target while changing offset in both directions, changing/restoring a dash entry, clearing/restoring dashes and recovering from a rejected NaN interval. Complete rasters must restore exactly and an unrelated sibling must remain unchanged. The coupled GuidelineIntegration corpus owns dash normalization, caps, stock-reference phase and explicit unsupported profiles.

An ImageBrush with a null ImageSource paints transparently for supported fill and pen paths, including rounded rectangles. The retained regression checks the complete background/sibling raster and source clear/recovery after a named nonempty ImageBrush rejection. General bitmap ImageBrush painting remains unsupported.

The process-rendering-preference regression starts with Default, sets SoftwareOnly/Default/SoftwareOnly and reads the process-wide value from another thread. Both invalid negative and upper enum values preserve the previous preference and keep the existing InvalidEnumArgumentException contract. Genuine retained CPU pixels remain correct under both preferences. The portable backend stores the requested preference; both values currently use its selected CPU profile, with no hardware-rendering claim. The ordinary Windows WPF native branches remain unchanged. Use --render-preference-only for this focused non-UI check.

Use `--drawing-image-only` for three focused DrawingImage regressions. They
exercise source bounds mapped into a nonuniform destination, nested images and
clips, empty drawings and zero-sized destinations, sibling state restoration and
retained child mutation, removal and restoration. The drawing is traversed through
the existing retained walker rather than flattened into a bitmap. All three
reproduce the previous unsupported-storage diagnostic against the released
CombinedGeometry-only family. The joint imaging/rendering family passes all
three focused cases and all 62 rendering cases on Windows and Linux. Separate
geometry-bounds comparisons retain their explicitly documented backend scope.


Content-free ContainerVisual subclasses use the same retained child traversal, transform, clip and invalidation rules as ContainerVisual. DrawingVisual and UIElement keep their existing content dispatch. HostVisual remains explicitly unsupported because it hosts a separate composition target; Viewport3DVisual and effects retain their named diagnostics. The regression checks derived-container child pixels, mutation, remove/re-add and sibling state recovery. The genuine PF UIElementIsland integration is verified separately by the FlowDocument owner.

Use `--drawing-brush-only` for six DrawingBrush checks. The bounded profile covers
rectangle, rounded rectangle, ellipse and geometry fills with TileMode.None or
Tile. The existing drawing walker records a picture shader using the same
viewbox, viewport, stretch, alignment and brush transform mapping as VisualBrush.
The viewport defines the repetition period, including transparent Uniform
padding. No persistent picture cache or new rendering engine is introduced.
DrawingBrush pens, glyph foregrounds and Flip modes retain named rejections, as
do unsupported operations inside the source drawing such as opacity masks.

The source-derived Classic theme check uses the two square gray/white ToolBar
Thumb pattern with absolute 4x4 viewbox and viewport at 96 and 192 DPI. A second
tiled check exercises Uniform padding, nonzero source coordinates, both brush
transforms and an outer transform with guidelines. The other checks cover
non-tiled Uniform mapping, clipping, opacity, sibling state, empty content,
freezing and dispatcher-driven child mutation followed by removal and restoration.
The four static profiles are calibrated against stock WPF 10.0.12. The released
portable family rejects DrawingBrush before pixels are painted. The later actual
NINA paint exception identifies the brush type and DrawRectangle entry point;
it does not establish which retained brush instance caused it. The Classic
ResizeGrip tile and NINA camera_shutter/Observatory Uniform resources are known
source profiles, not identified live owners.

Use `--blur-only` for seven focused Gaussian BlurEffect checks. The selected
profile is NINA's default Gaussian kernel and Performance rendering bias under
finite axis-aligned transforms. The display layer uses the current
animated Radius, truncates the local radius, multiplies by the smaller basis
scale using float arithmetic, truncates again and caps the device radius at 100.
The Gaussian sigma is one third of that device radius. Radius zero preserves the
unfiltered pixels exactly. Other kernels, biases, effects and skewed transforms
remain explicitly unsupported; this is not general Effects compatibility.

The checks cover radius and child mutation, removal and restoration of the
previous effect, genuine zero-duration 0 -> 10 -> 0 animation, grouped descendants,
visibility, opacity, own/ancestor clipping, failure recovery, transforms and DPI.
They also retain unchanged Gray16 source samples and the clone captured before
blur is enabled. Portable retained checks observe the registered target after
dispatcher processing without manually rendering each mutation. The shared
stock reference uses fresh public RenderTargetBitmap captures and a public
CompositionTarget.Rendering subscription to advance its windowless animation
clock. Native alpha profiles and raw display pixels are retained separately;
Skia and Windows Gaussian raster bytes are not asserted equal. After the seven
focused checks pass, `--blur-only --capture-blur=<absolute JSON path>` records the
same twelve raw display profiles for a measured comparison with the native
reference. No universal raster tolerance or complete Effects compatibility is
claimed. The combined family passes all seven focused checks and all 75 rendering
checks on both OSes. The twelve raw Windows and Linux captures are identical.
Against stock WPF, the Radius 10 fixture differs by at most 4/255 at 96 and
192 DPI; its omitted halo pixels all have native alpha 1. Radius 3 and 3.9
differ by up to 18/255, the nonuniform-scale fixture by 11/255 and the capped
100/200 fixtures by 1/255. Both clips exactly match their full-image crops within
each backend and the measured half-coverage geometry agrees. These measurements
apply to the declared 96x80 and 192x160 fixtures, not arbitrary content. Actual
NINA drag, mouse-up and Escape restoration remain a separate application gate.
Existing
unsupported-effect controls use DropShadowEffect at the derived container,
visibility helper and VisualBrush source boundaries.

The earlier DrawingBrush joint family passed all six focused cases and all 68 rendering cases
on Windows and Linux. Picture shaders normalize their tile origin, so the shader
matrix restores the viewport origin before the brush transform and outer device
transform. A negative viewport with scaling and translation checks that order
against stock WPF. Tested guidelines belong to outer placement; the existing
walker does not apply DrawingGroup.GuidelineSet inside the source drawing. None
of the four inspected NINA/Classic brush declarations uses that property and
general source-guideline parity remains unqualified.

`--image-brush-only` runs six ImageBrush fill checks. The supported profile is
TileMode.None with a BitmapSource backed by portable bitmap storage. Rectangle,
rounded rectangle, ellipse and geometry fills share the existing TileBrush
viewbox/viewport mapping and DrawImage conversion and inherited sampling path.
Bitmap content bounds use Width and Height in DIPs, including source DPI. The
outer shape, viewport and mapped content bounds are intersected in device space
after guideline placement. That single coverage path is painted once through
the existing bitmap shader and sampling code, avoiding repeated antialias
attenuation where their edges coincide. The previous walker state is restored.
Brush-local BitmapScalingMode does not override the visual or ancestor mode.
Null ImageSource is transparent even when its unused tile mode is Tile or Flip.
Nonempty Tile/Flip, non-bitmap sources, ImageBrush pens and glyph brushes retain
named unsupported diagnostics. This does not qualify general TileBrush support.

The shared windowless stock oracle runs the same public fill scenes with
`--image-brush-only`. It checks UniformToFill thumbnail cropping, other stretches,
alignment, absolute viewbox/viewport with translation, 384/768 source DPI,
shape bounds, clips, opacity, siblings and caller state. Four-pixel color bands
provide flat interiors under both backends without asserting identical filter
bytes at color boundaries. Their 16x8 pixels retain a 4x2 DIP extent at 384 DPI
and a 2x1 DIP extent at 768 DPI. Sampling scenes compare ImageBrush with DrawImage at
interior crops including transitions under inherited NearestNeighbor and Linear
at 96/192 target DPI. Real UIElement parent/child scenes exercise the public
RenderOptions metadata callback. Both backends require the two modes to differ
within that crop, child override/clear to restore the ancestor mode and ancestor
clear/restore to restore default Linear and the original mode respectively.
Full-image alpha equality against DrawImage catches fractional guided edges at
both target DPIs. Five additional profiles compare fractional unguided Fill,
Uniform letterboxing, an inset absolute viewport, rounded rectangles and
ellipses against public image or solid-fill controls. All five profiles have
exact brush/control alpha equality in the windowless native reference at both
DPIs. On Skia, rounded and ellipse profiles at 192 DPI differ from their
independent solid controls at 12 and 23 alpha cells respectively, each by one
unit. A disposable shader/path probe reproduces that rounding with and without
path intersections. Only those two portable profiles allow that measured
one-unit difference; occupied-cell support and all other whole-alpha checks
remain exact. This is separate from pre-existing cross-native curve raster
differences: the solid rounded profiles differ by up to 44/60 alpha units at
96/192 DPI and solid ellipses by 55/76, while ImageBrush differs by 44/59 and
55/76 respectively. These are measurements of these fixtures, not an extension
of an earlier corpus's 17/32 measurements or a universal bound.
`--capture-image-brush=<absolute JSON path>` retains all 28 raw
control/brush images for measured comparison. There is no universal pixel
tolerance claim. The separate NearestNeighbor 192 DPI texel-boundary color
difference shared by direct DrawImage and ImageBrush remains distinct from the
brush-only edge-coverage regression.
The explicit `--capture-image-brush-on-failure` diagnostic option permits those
captures after a failed focused check; it preserves every check and the failing
exit code.
Portable retained checks observe the registered target after dispatcher work
without manually rendering changes. Stock takes fresh public RenderTargetBitmap
snapshots. Both exercise source A/B/null/A, WriteableBitmap pixel mutation and
restoration plus unchanged Gray16 and RGB48 source bytes with nontrivial low
bytes. Unsupported diagnostics are
portable-only checks because stock supports additional brush profiles.
The older retained source-clear/recovery and visibility rejection controls use
nonempty FlipXY so they continue to exercise unsupported content after basic
bitmap fills become supported. Their clear, restore and hidden/visible pairs
remain active.
