# Pinned genuine NINA astronomy on Linux x64

`eng/portability/Build-NinaPortableAstronomy.ps1` builds the complete pinned NINA.Core and NINA.Astrometry source assemblies against one supplied portable WPF family. Its 670-file manifest covers both assemblies, the original SOFA 2023-10-11 distribution, NOVAS C3.1, NINA licensing and common assembly identity. The helper verifies source/tool/closure hashes, regenerates the original protobuf API with the existing pinned compiler and preserves Core's original XAML/resources. It changes six original files and adds one private assembly resolver. Windows branches retain the original PInvokes and names. The sixth source boundary makes only the Linux default DatabaseInteraction constructor use `Path.Combine(CoreUtil.APPLICATIONTEMPPATH, "NINA.sqlite")`; the explicit connection-string constructor and all queries stay unchanged.

The only native calculation-source changes are the NOVAS catalogue identifier field and make_cat_entry argument from platform `long` to `int32_t`. All internal astronomy arithmetic stays in the original C and managed sources. `build-native.sh <owned-source> <owned-native-output>` builds actual ELF libraries and the original native validation programs with GCC. Source/output paths must contain no whitespace. GCC's command-line `__declspec` macro removes the Windows export annotation without changing the source distribution. Keep source licenses and version data with any deployment.

Build `Qualification.csproj` using SDK 10.0.401 with `ImportDirectoryBuildProps=false`, `ImportDirectoryBuildTargets=false`, isolated output/intermediate paths and no package sources. Set `AstronomyProfile=stock` or `portable`, `OriginalManagedDirectory`, `EphemerisPath`, `SofaLibraryPath` and `NovasLibraryPath`. Portable additionally requires `NinaCorePath`, `NinaAstrometryPath` and `FrameworkRuntimeDirectory`. The original closure, WPF family and existing native data must already pass the build helper's input verification. Run the resulting console with one absolute JSON report path. It opens no App, window or equipment device. Use the same pinned JPLEPH file for both OSes.

`Compare-Results.ps1` compares the public numerical results to the original Windows managed/native implementation at 1e-10, all 66 native/managed/stock size/offset observations, original SOFA validation, original NOVAS solsys3 checkout and the original full checkout's printed coordinates at 1e-8. The full reference uses DE405 while the pinned genuine input is DE421, so its header differs and one printed right ascension differs by 1e-9 hours. This is a distinct check from the bit-identical same-JPLEPH managed comparison.

The native ephemeris probe runs once per process: pass an absolute existing JPLEPH path plus expected status 0, an absent owned path plus 1 or a deliberately truncated owned copy plus 2. The valid process opens, records the genuine DE421 range and closes once. The original NOVAS ephemeris manager does not clear its global FILE pointer after close or failed header reads, so repeated close/reopen after those operations is not qualified.

Linux explicitly rejects the unused application compatibility methods NOVAS.CalDate, SOFA.Ae2hd and SOFA.Hd2ae. They expose return values for native void functions. No return value is invented. NINA.Test/SkySurvey/SkyMapViewportProjectionTest.cs uses Hd2ae while ignoring its return, so that existing unit-test helper is outside this bounded profile. `set_racio_file` is absent from the original DLL and remains an unimplemented, unused private declaration. CIO binary file layout is not qualified and no CIO file is staged.

`NighttimeQualification.csproj` additionally uses the real ProfileService, Profile and NighttimeCalculator with a minimal System.Windows.Application resource owner. It creates no NINA.App, startup path, window, view or VM. Pass the same build properties plus `SqliteLibraryPath` for the original SourceGear SQLite native library and `DatabaseSourceDirectory` for all 17 pinned original SQL scripts. Run with report path, fresh owned state ending in `NINA` and the genuine stock-initialized database path. The fixture requires the exact 7,532,544-byte stock database SHA256 `4DD072B013F015C3E4460B0E6AFF29538DE2774331293726F81E8DF14E2DDAAC`, schema version 16, 23,085 EOP rows and 16,857 DSOs. It obtains the actual default filename through SQLite PRAGMA database_list and checks owned-path containment after computing the original nighttime events.

The original Linux path can silently create a duplicate genuine auto-initialized catalog at a sibling filename containing backslashes. The failing path-containment test preserves that evidence; numerical finiteness alone cannot detect the defect. The fixed path uses the intended original database. Covered reference dates are 2024-10-01 and 2024-10-02. All 36 EOP, lunar illumination/phase, solar/lunar rise/set, twilight and altitude values agree with original Windows within 1e-10. Original plot series and cache identity are verified. The original data ends on 2025-03-15. A separate 2026 sample retains and records the original warning and nearest UT1-TAI holding behavior, without claiming current IERS accuracy.

Full App/MainWindow, original workflow views and simulator capture remain separate gates. No synthetic nighttime service, downloaded ephemeris or replacement calculation is used.
