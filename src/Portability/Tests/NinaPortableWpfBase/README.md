# NINA WPF.Base framing boundary

This wrapper builds the complete pinned NINA.WPF.Base assembly with its original identity and 37 BAML resource keys. The offline generated project follows the existing Application and Image wrappers. It uses the whole declared owned WPF family, owned markup compiler family, pinned MVVM generator and declared Core, Image and Astrometry component bytes. The producer emits PE/PDB source proof and a component intake. Public API and behavior qualification remain separate checks.

Only `SkyMapRasterRenderer.cs` and `SkyMapImageCache.cs` are adapted. Windows keeps its GDI renderer behind a Windows resource holder. Linux draws the original scenes with existing WPF APIs into the original reusable mutable bitmap. Default mode retains the original fresh `DrawingImage` composition with live cached sources. SoftwareOnly retains a half-size preview with ceiling dimensions and nearest-neighbor expansion. Frozen decoded NINA tiles draw directly while the original cache lock protects their lifetime. External placements retain the 64-entry identity/flip snapshot cache.

The original cache decoder options, projection math, source samples, active-tile protection, byte/count budgets, cancellation and disposal stay intact. No GDI compatibility layer, dependency or framework API is introduced. Sky Atlas preview generation and network survey processing are outside this renderer boundary.

`Qualification.csproj` uses the existing dependency-free C# qualification pattern. `RendererCases.cs` and `CacheCases.cs` retain observable checks from the pinned original `SkyMapRasterRendererTest.cs` and `CacheSkySurveyTest.cs`. The Windows reference run records real hatch pixels and JPEG cache files through the original classes. The check run uses those files through the original cache loader. It checks both composition modes, bound pixels, flip/rotation, clearing, preview coordinates, DSO/label placement, mutable-source snapshots, cache eviction, cancellation recovery and disposal. It compares the full exported public API semantically.

The original GDI hatch has an eight-device-pixel diagonal pattern. The half-size preview scales that device pattern by the actual ceiling-sized scratch ratio. Qualification compares the strongest-stroke positions and nearest expansion against bounded Windows references. WPF retains the original paint colors and font point sizes converted by 96/72. GDI and WPF antialiasing and platform font metrics can differ; exact text pixels or font identity are not claimed. The mask uses device-rounded vertices corresponding to the original `SmoothingMode.None` so odd preview edges remain opaque.

All 42 renderer/cache checks pass on stock Windows, adapted Windows and Linux, including eviction with a long-lived renderer and the original JPEG cache save/reload path with all three thumbnails. Linux used the complete source-proven imaging/rendering family with manifest SHA-256 `1D4CAAE2B891A02A7433D427EF8452067C16F5C29D538B8FAD134C1902816339`. The earlier failures against the family without DrawingImage rendering and cached-image decoder options remain recorded separately.

Full framing VM and application interaction require separate integration checks. The recovered Framing18 workflow reaches original view construction, then fails during initial painting of an empty button-template Path. Its stretched empty geometry has NaN translations that the portable renderer incorrectly attempts to convert. This framework fault leaves Framing18 unqualified; it does not change the 42 component results.
