# App-local WPF BAML runtime integration

This gate reuses the exact XAML, CLR code, assembly name and text resource from `../MarkupIntegration/Fixture`. It imports the genuine app-local markup compiler and original `Microsoft.WinFX.targets`, replacing the stock WindowsDesktop framework reference with ordinary project references to the current-source portable WPF implementation. It targets `net10.0` and has no `Microsoft.WindowsDesktop.App` framework requirement.

An additional eight-byte opaque resource is embedded under an unknown extension and an extensionless alias. Actual `Application.GetResourceStream` checks preserve its bytes and octet-stream MIME type. The original Unicode TXT resource is read through relative and absolute pack URIs plus case, query and fragment variants; each must preserve bytes and return `text/plain`. A compiled XAML URI must continue to expose `application/baml+xml`.

The runner checks loaded framework identities, hashes, app-local paths and default assembly load contexts, then constructs the real compiled view. On successful construction it exercises generated fields/events, repeated initialization, local control types, merged dictionaries, compiled templates/binding and the pack resource. A construction failure is reported with its complete exception chain and stack trace, blocks dependent checks and returns nonzero. The entry point isolates framework-dependent methods so the first runtime loading or native boundary failure can be captured as JSON.

The message-font check resolves an installed physical face and measures text through actual `FormattedText`. A separate actual `Run` verifies TextElement default inheritance. Both runtime origins explicitly reject loading DirectWriteForwarder on the portable path. Process exit must also be checked: emitted successful checks cannot establish success if shutdown subsequently fails.

Run from `src/Portability` with the workspace CLI/cache settings:

```text
dotnet build Tests/MarkupRuntimeIntegration/Runner/Runner.csproj --nologo
dotnet run --no-build --project Tests/MarkupRuntimeIntegration/Runner/Runner.csproj
```

Use the workspace Linux SDK under WSL for Linux execution. Builds and generated markup are isolated below `artifacts/portability/markup-runtime-integration` by OS and source project directory. `MarkupRuntimeArtifactSuffix` selects an additional isolated test output directory; `PortableFrameworkArtifactsDir` selects a fresh full framework graph. The fixture's files are linked from the existing oracle rather than copied or reduced.

The full source framework graph builds on Windows and Linux. Genuine Windows metadata used to compile platform-specific framework APIs is not a Linux runtime implementation. These fixture results do not establish NINA, third-party control or complete desktop application compatibility.

With the portable settings/generic resource policy, official managed XAML access asset selection and portable MIME fallback, the fork-produced fixture passes all seven checks on both Windows and Linux. The independent unchanged Microsoft-produced fixture passes all five checks on both hosts, including its actual control template and templated-parent binding. All four processes exit zero. The MIME fallback preserves the original known XAML/BAML/JPG/XBAP mappings, uses `text/plain` for TXT and `application/octet-stream` for unknown or extensionless resources. It does not query OS associations or sniff bytes; the ordinary Windows implementation retains UrlMon.

`RuntimeAssemblyEvidence.cs` verifies the unchanged official `System.Windows.Extensions/10.0.13` asset `runtimes/win/lib/net10.0/System.Windows.Extensions.dll`, SHA-256 `54163AEF0B78412550C50FFE0826E53B6F39DD3CC718D1EB9D16B73C27FD75F9`. Both origins load it through the normal default load context. Dependency metadata must select that same asset and runtime configuration must require only `Microsoft.NETCore.App`. No custom resolver, assembly rewrite or WindowsDesktop shared framework is used.

## Independent Microsoft compiler origin

`MicrosoftOracleRunner` is a separate gate for the unchanged existing `WindowsReference/FixtureControls` binary. Its BAML was generated by the installed Microsoft SDK 10.0.401 compiler, `PresentationBuildTasks, Version=10.0.12.0`. It is independent of the fork's compiler output. `MicrosoftCompilerOracle.json` pins the assembly SHA-256, original generated-source SHA-256, installed compiler SHA-256 and original targets SHA-256.

On Windows, `Capture-MicrosoftCompilerOracle.ps1` verifies this provenance and freezes an unchanged copy under `artifacts/portability/markup-runtime-integration/microsoft-oracle`. The runner uses a binary reference to this archive. It does not reference the original fixture project or regenerate any of its code or BAML. It rechecks the loaded binary's hash and generated compiler-version attribute at runtime.

```text
./Tests/MarkupRuntimeIntegration/Capture-MicrosoftCompilerOracle.ps1
dotnet build Tests/MarkupRuntimeIntegration/MicrosoftOracleRunner/MicrosoftOracleRunner.csproj --nologo -m:1 -nr:false -p:UseSharedCompilation=false
dotnet run --no-build --project Tests/MarkupRuntimeIntegration/MicrosoftOracleRunner/MicrosoftOracleRunner.csproj
```

The frozen binary is shared with the Linux build. The latest isolated full-graph results use `final-policy/` test output suffix and `framework-markup-final/{windows,linux}` framework roots. Separate `microsoft-baml-final-{windows,linux}.json` and `markup-runtime-final-{windows,linux}.json` evidence records compiler origin, candidate hash, loaded framework paths/hashes and actual runtime behavior. Matching `*-process.json` files record actual exit codes. `markup-runtime-final-baml-equivalence.json` verifies that all five fork BAML/pack payloads remain byte-identical between hosts. Earlier `*-runtime-*.json` and `markup-mime-red-*.json` evidence preserves the previous failure boundaries.

Isolated loader diagnostics are available through the source runner with `--probe-font-cache-dpi`, `--probe-generic-run-constructor`, `--probe-generic-paragraph-constructor`, `--probe-span-vector-constructor`, `--probe-formatted-constructor` and `--probe-typography-constructor`. These diagnostic results describe a trigger; they are not runtime compatibility passes.

Earlier byte comparisons matched Windows and Linux fork-compiler artifacts within each reference closure. Before the namespace-resolution regression added a compile-only Ribbon reference, the portable-source fixture's BAML was 105 bytes smaller per file than the stock-reference fixture because the stock SDK also referenced Ribbon. The extended source fixture now intentionally includes that unused namespace candidate. These fixture reference changes are separate from the frozen unchanged Microsoft-produced binary and NINA gates.

## Optional BAML namespace assemblies

The runner adds four checks for namespace assembly resolution, bringing its total to eleven. A bounded `NamespaceValidation.xaml` page in the existing fixture compiles a deferred template with an explicit `Path=(Validation.Errors)` binding. The fixture references unchanged official Ribbon metadata only for compilation, with `Private=false`; its BAML includes Ribbon in the presentation-namespace assembly map while the runtime output contains no Ribbon assembly. Applying the real template must resolve the actual Validation.Errors collection. The explicit Path syntax exercises PropertyPathConverter, matching the unchanged NINA TextBox resource failure; the Binding constructor shorthand follows a different conversion path.

A separate small contributor assembly proves that every available namespace candidate still loads, even when the requested type already exists in a loaded assembly. Its distinct type must then resolve through the same real schema context. Internal schema setup uses test reflection and adds no production access API. Required BAML type-ID assembly resolution, a named missing XAML type and malformed assembly identities remain errors. A scoped fixture-only load-failure callback supplies no assembly and verifies that a different-name dependency error and a bad-image error remain failures; it is removed in `finally`.

The production change is limited to `PORTABLE_WPF` namespace-candidate loading. It skips a FileNotFoundException only when it has no inner failure and its parsed name/public-key token match the requested mapped assembly. Wrapped dependency errors, malformed exception identities, explicit assembly/type resolution and all other load errors retain their existing behavior. All available mapped assemblies are still loaded. The ordinary Windows source branch is unchanged.

The initial regression fails both the absent-candidate lookup and the genuine compiled validation template before the repair. The original NINA six-check replay remains separate and immutable: its Linux layout failure establishes the original Microsoft BAML boundary, while its Windows portable layout probe exceeds the qualified Linux native asset profile. These focused source-runtime checks do not qualify a new runtime package, NINA source rebuild, native input or complete NINA startup.

## Managed document inline profile

Run and Span subclasses, including Bold, Italic and Hyperlink, retain the actual
TextContainer edge symbols in the managed bottomless paragraph source. Genuine
TextProperties supply inherited fonts, language and brushes. Decoration scopes
use the existing TextSpanModifier and matching TextEndOfSegment, preserving an
outer decoration brush when a child Run has a different foreground. LineBreak
consumes its two real symbols. Empty Run/Span elements use the original stock
ComplexLine zero-width-space metric technique for their two edge symbols.
Preceding text includes consumed nontext symbols and the actual preceding Run's
culture rather than the paragraph default.

The `--flow-document-inline` cases exercise genuine nested style/hyperlink hits,
forward/reverse selection, wrap restoration, visible decoration/foreground
mutation and restoration, empty metrics, LineBreak, source run contracts and
failure/recovery after a reused real block child. The stock oracle runs the same
positive fixture methods using WindowsDesktop 10.0.12 and genuine ComplexLine
source inspection. The test explicitly clears Hyperlink's own default
TextDecorations, matching the observed original NINA callback, so distinct outer
decoration and child text colors remain separately visible.

Geometry follows the existing portable line-box caret profile. With mixed font
sizes, stock can return a small Run's glyph-height rectangle shifted within the
line while the portable view returns that line's full box. Tests require the
stock-calibrated next-line displacement, valid edge geometry, actual ink changes
and restoration; they do not claim per-run rectangle parity. Color checks observe
hue contrast for thin antialiased decorations rather than requiring opaque
reference pixels. LineBreak selection preserves unchanged TextRangeBase behavior:
Environment.NewLine yields CRLF on Windows and LF on Linux.

Directional inline embedding remains explicitly unsupported, as do
InlineUIContainer, figures and floaters in this slice. Core formatter property
limits remain in force. Lists, markers, sections, tables, pagination, editable
RichTextBox and the full original link/composite recipes remain separate gates.

Styled ink qualification requests named Arial on Windows and the already installed
Liberation Sans family on Linux. It requires genuine
present Bold/Italic GlyphTypeface faces with no simulations, then observes both
style mutation/restoration rasters. In the pre-cleanup runs, Linux Arial fallback
selected DejaVu Sans, whose installed catalog lacked Italic, so the face guard
failed. Core font fallback selection is unchanged. Empty-inline metrics and source
contracts retain the fixed DejaVuSans.ttf fixture. A stronger fixture using only
that Regular file previously passed stock but failed the portable Bold ink
mutation: existing Core file-font selection does not synthesize missing style
faces. Those generated failure reports were deleted during external cleanup;
fresh qualification is pending. This slice does not repair or qualify single-file
synthetic-style parity.
