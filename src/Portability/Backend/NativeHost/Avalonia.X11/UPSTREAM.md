The project compiles 80 unchanged files, verified derivatives of `GlibDispatcherImplBase.cs`, `X11Window.cs` and `X11ClipboardImpl.cs`, a renamed derivative of `Avalonia.FreeDesktop/DBusSystemDialog.cs`, original shared raw-event grouping code and unchanged source generators. Every build verifies the original GLib dispatcher file SHA-256 `5070CE8FC7CD809B06C4B424CD1330F7D33CC0CCC36A48303E88B25B37922965`, then replays the one exact patch hunk into `.portable-derived/<OS>/GlibDispatcherImplBase.cs`. The derivative's resulting SHA-256 is `A5057CE83D488795BD8A37106847B46C3F14B79133A19EBFF9F1C386208FA2DC`.

The same exact-hunk task verifies original `X11Window.cs` SHA-256 `E8552DF43A2EB2B045317E92E3584A35BB07401DDBA665CB40AAB9CDC948079F` before replaying `PreserveMinimumDpiExtent.patch` into a separate per-OS derivative, SHA-256 `22A2D6B7EBF1F83D9E47C0FA4EA289828873C8DF22652DC92A4D8067433910C1`. Only `WindowResizeReason.DpiChange` preserves each converted extent at the legal native minimum of one pixel. This prevents a valid 1-pixel window at 96 DPI becoming 0.666 DIP at 144 DPI then requesting illegal zero pixels when returning to 96 DPI. The corrected pixel size flows through the original hints, main/render-child configure and existing cache/callback path. Explicit zero/subpixel user requests remain rejected by the owned bridge; the patch adds no logical zero-size contract or fabricated host metrics.

`PortablePortalStorageProvider.patch` verifies original `Avalonia.FreeDesktop/DBusSystemDialog.cs` SHA-256 `130DFD301877AB9451D319A0970E1050030F52733FA1C4D6C720AC46EDA1888A` and derives the internally renamed `PortablePortalStorageProvider` in this signed X11 assembly. Its resulting SHA-256 is `B37B3BE29FF112626167CFF057F3FECE11FC22C06BF2A300FB46C9419B55015A`. The original FreeDesktop assembly and source remain unchanged. This reuses the existing request subscription, request-path verification, filter mapping and parent lease, with three bounded corrections: response1 yields cancellation while failure/malformed success completes the task without throwing out of the observer; owner cancellation awaits the actual method reply and sends `Request.Close` once; Save preserves the final portal path instead of post-appending an extension after native confirmation. The production bridge exposes only Open/Save through the actual X11 parent, bypassing the GTK fallback that changes process environment. Folder picking is outside this bridge's declared scope. Original source and API red evidence are retained with the protocol fixture artifacts.

`BoundClipboardManagerWait.patch` verifies original `Selections/Clipboard/X11ClipboardImpl.cs` SHA-256 `BC885C44363ECD9F3F314A66E6018250FED7964F22F708012D04422AF1F0BC45` and derives a separate per-OS file, SHA-256 `0458F48326792B19B8D9D1A453A7B4EAEFD789D5C7F57B60645F95EBD4EF0405`. The original clipboard source remains unchanged. After actual CLIPBOARD ownership and the existing SAVE_TARGETS request, the optional clipboard-manager acknowledgement waits at most one second. An acknowledgement completes immediately; only timeout is treated as successful best-effort completion with session ownership intact. Native ownership/request errors remain visible. A manager which never acknowledges therefore cannot indefinitely block public SetText or leave an already-published Cut waiting. Neither timeout nor acknowledgement proves persistence. No second event loop, delayed-rendering emulation or clipboard-manager service is added.

The new typed private-API facade returns Avalonia's existing `ManagedDispatcherImpl.IManagedDispatcherInputProvider` interface over its actual Xlib event dispatcher and manual grouped input queue. Its small provider delegates pending Xlib events to the original `X11EventDispatcher.DispatchX11Events`, then dispatches at most one already-grouped input through the existing manual provider. The owned WPF adapter calls it before waiting for more OS events. It creates no queue, translates no WPF priorities and changes no Avalonia application behavior when unused.

The first native regression requiring this seam enters a WPF nested frame from an actual XTest-delivered KeyDown. Avalonia's GLib socket callback has already drained KeyUp into the manual managed queue, leaving no readable X11 socket. A bare GLib iteration cannot dispatch that queued release until the outer callback returns. `Dispatcher.RunJobs` also cannot help: the manual queue's `Add` only enqueues; the separate automatic queue implementation posts dispatcher jobs. The manual queue removes each item before invoking its callback and has no recursion guard, so the existing provider can safely dispatch the next item on the same owner thread.

The second regression occurs before grouping: `HasPendingInput` calls `XPending`, which can read socket bytes into Xlib's own event queue. The GLib file descriptor source may then be non-readable even though Xlib already holds the key events. Delegating that existing native queue to its original event dispatcher closes this gap. The integration runner repeatedly probes pending native input before dispatch to verify that querying does not strand it.

The third regression concerns the native C callback boundary. The upstream `RequestBackgroundProcessing` idle callback invokes `ReadyForBackgroundProcessing` without the exception guard used by its signal and timer callbacks. A thrown Avalonia Background operation therefore aborted the native process with exit 134 instead of reaching the WPF frame's managed catch. The one source patch catches that callback's exception and routes it through the existing `HandleException` path. The configured external logger can then capture it and the owned pump rethrows after `g_main_context_iteration` returns. Other callback behavior is unchanged. Separate signal and Background tests require both the native callback and the managed rethrow in the exception stack and verify subsequent Avalonia/WPF dispatcher work. The direct managed input-provider exception case remains distinct.

The rebuilt assembly retains `Avalonia.X11, Version=12.1.4.0` with the original `c8d484a7012f9a8b` public signing identity. Its informational version explicitly identifies this source adaptation and upstream commit. Public signing preserves identity for existing friend access; it is not an upstream signature. The original public key is read from the verified upstream `build/AvaloniaPublicKey.props`. No metadata, assembly references or package DLLs are patched.

The native Window peer adds a separate typed `ExternalWindowBridge`. The low-level `IWindowImpl` cannot receive native events without an `IInputRoot`, whose abstract internal members prevent an external implementation. The existing X11 assembly's original Base friend access permits an inert `InputElement` token implementing that interface. This token has no Avalonia control tree, layout, renderer or input-manager routing. Actual WPF reports are consumed exclusively by the genuine WPF source/provider.

The Window bridge uses the backend's existing X11 display for native focus queries/acquisition, actual pointer grabs, physical screen hit queries and XKB key snapshots. Its observer chains the existing native event hook, returns the previous hook's result and does not consume native events. It observes normal focus changes and capture loss and restores the prior hook after the last peer is disposed. It also reads the actual XSETTINGS selection owner's bounded property and checks framebuffer upload errors after synchronizing the upstream framebuffer's deferred display. These methods create no native event queue and do not replace original X11 dispatch. They are an additional maintenance obligation beyond the earlier dispatcher facade and exception guard.

The same facade queries actual client dimensions/screen origin, bounded EWMH frame extents and state for a single host metrics publication. This bypasses a confirmed stale upstream Configure cache without changing that cache or the original dispatch jobs. The owned peer captures the complete result and DPI before notifying WPF. No synchronous event pumping or server grab is used.

The owned `X11Window` partial in that facade also contains the pinned `Resize` request body from upstream lines 1331-1346. An explicit WPF size request must reach X11 even when it equals Avalonia's delayed Configure cache but differs from actual server dimensions. This narrow copy omits only the cached-equality return and the `force` behavior; it preserves native pixel rounding, size hints, render-child resizing and original pre-map/popup acknowledgement. Mapped Window geometry remains authoritative from native events and fresh server metrics. The peer schedules its existing coalesced metrics publication after the request, including when the server already has the requested size and emits no Configure event. Maintaining this copied request body against the pinned upstream implementation is an additional source adaptation obligation.

Before size hints or either configure request, the owned resize entry rejects converted client dimensions below one native pixel with a named managed `PlatformNotSupportedException`. This initial profile does not implement zero-logical-size mapping. It does not clamp the request, fabricate geometry or leave a BadValue error pending in X11. Valid one-pixel extents retain the original request and native acknowledgement path.

The unchanged upstream development generators use the upstream-pinned Roslyn `Microsoft.CodeAnalysis.CSharp` 4.14.0. Their separate build project compiles only the upstream generator sources and shared attribute support. Both Windows and Linux outputs remain under separate artifact directories.

The signing key and derived source are written only when their bytes differ. Verified second builds on Windows and Linux skip `CoreCompile` and leave both files and the compiled X11 assembly unchanged. This avoids recompiling all upstream sources on an ordinary no-change build.

`AVA3001` intentionally reports the unstable private API dependency. `CS0649` also remains visible for the unchanged upstream `X11Screens.MonitorInfo.RefreshRate` field. Only that source project permits the existing warning without treating it as an error; owned adapter and test source retain warnings-as-errors.
