# Local portable distribution

This is the app-local distribution path for `net10.0` on Linux x64. It keeps the deliberate WPF assembly version 10 identities inside distinct `Wpf.Portable.Runtime` and `Wpf.Portable.Sdk` package IDs. Public signing preserves the reviewed identity contract; it does not authenticate the fork as a Microsoft build.

The runtime is a closed, explicitly inventoried bundle of genuine framework/backend managed assemblies and Linux x64 native assets. It does not contain reference assemblies, cycle breakers, fixtures, Windows native binaries or the .NET runtime. The SDK carries the original WinFX targets, the real PresentationBuildTasks compiler and measured non-host task dependencies. Genuine Windows metadata needed for source compilation lives only in `tools/contracts`, with copy-local disabled. MSBuild's own assemblies remain supplied by the invoking .NET 10.0.401 SDK.

The SDK adds its exact runtime package reference, owns markup item defaults and uses package-relative paths. Runtime policies import transitively, remove the .NET WindowsBase shim and select the qualified bundled Extensions/native-host identities. Conflicting consumer versions fail with a named diagnostic instead of silently substituting unrelated assemblies.

The runtime includes the complete original-source Windows.Core helper as AnyCPU IL with its original ECMA binding identity. This replaces its former compile-only Windows image classification and contributes to the manifest-derived managed runtime inventory. Source pin, manifest and MIT license travel with the runtime notices. The ordinary project graph carries its existing Nrbf dependency, while the SDK no longer carries a competing helper contract. The existing runtime-manifest check exercises the genuine managed DataObject store and interface wrapping under the default CLR. This does not port OLE, GDI or other Windows services declared by the helper; native clipboard transfer uses the host backend.

Qualification requires an external package-only consumer with its own SDK pin and local-only NuGet configuration. It must compile and run real x:Class/BAML, templates, binding, events, companion dependency properties and Unicode/case-sensitive pack resources. Framework-dependent execution precedes Linux x64 framework-dependent and self-contained publish. The native check uses the genuine packaged Window/backend with OS-injected input and compiled BAML. The package manifest records identities, hashes, provenance and notices; the output audit rejects unlisted runtime files.

The profile has explicit product settings and selects the genuine source-built Classic dictionary. On both hosts the package check constructs ordinary UserControl, Button and TextBox default templates, verifies the real TextBox content host and lays out native-free UserControl/Grid content. Linux also measures and lays out Button/TextBox text using the package's native dependencies. Windows verification deliberately stops before text layout and checks that no Windows HarfBuzz or Skia library loaded; this Linux-only runtime bundle does not provide those native binaries. The full dictionary retains deferred resources whose dependencies remain unqualified, including non-null document formatting and native keyboard-repeat settings. Classic does not claim Windows desktop or Aero2 pixel parity. Arbitrary WPF binaries, other RIDs, trimming, NativeAOT and single-file publication remain unqualified. Desktop OS libraries remain prerequisites; no machine-wide .NET installation is replaced.

For native Linux X11 windows, call `NativeWindowHost.InitializeForCurrentThread()` in the application entry point before consuming WPF Dispatcher or system settings. The consumer fixture uses an explicit `StartupObject` for that ordering. Its explicit templates retain the native input baseline alongside the separate Classic default-control check. The selected original Extensions DLL qualifies managed XAML access scopes; its Windows-only sound and certificate operations remain unsupported.

Run `eng/portability/Build-PortablePackages.ps1` from the checkout. It creates a fresh distribution directory and a local feed containing the two WPF packages plus the exact official Linux runtime/host packs needed for the self-contained verification. SDK 10.0.401 also requests its ASP.NET runtime pack during transitive framework discovery; that original package is available in the offline feed but does not become an application framework reference or published runtime. `Test-PortablePackages.ps1` creates the independent consumer; `-HostProfile PrepareLinux` writes a Linux-ready copy for `Test-PortablePackages.sh`. `Test-PortablePackageContents.ps1` audits the archives and selected consumer outputs. Producer prerequisites remain the current source build prerequisites, including Perl; the owned Linux backend does not require prepared vendor UI sources. Consumer prerequisites are .NET SDK 10.0.401 plus the documented native desktop libraries; Xvfb and XTest belong to the verification fixture.

The Linux runner copies the prepared source into a fresh `/tmp/wpf-portable-package.*` directory and asserts distinct filename casing before compilation. NuGet cache, intermediate output, custom output, publication and execution all stay in that native Linux directory. It mirrors binaries and evidence back to the prepared artifact directory for inspection. Source and package caches are kept separate from the installed SDK. Fresh CLI homes disable automatic development-certificate generation and workload update notifications.

`Test-PortablePackageConflicts.ps1` verifies a genuine qualified Extensions package duplicate, rejects an older genuine package version and rejects unqualified publish profiles. The standard fixture uses the frozen Microsoft compiler oracle maintained by the existing markup tests; it verifies the recorded binary hash before copying and never recompiles the oracle. Application publication preserves the runtime's license, third-party notices and provenance sidecars. SDK dependencies CodeDom and MetadataLoadContext are pinned NuGet 10.0.13 host-neutral IL implementations. The first disposable Linux rehearsal rejected the Windows SDK's ReadyToRun MetadataLoadContext binary; host SDK implementation binaries are not used in the shipped task closure.

The same profile guard is packaged for both SDK and direct/transitive runtime PackageReference consumers. `Test-PortableRuntimePolicy.ps1` exercises ordinary Microsoft.NET.Sdk applications and a real intervening NuGet library. The fixture's passive compiler observer records already-loaded assemblies after genuine markup compilation and checks an earlier control invocation; it never loads either compiler dependency. Package archives are checked against complete content manifests, including notices and provenance. Original NuGet metadata is preserved byte-for-byte with the suffix `.nuspec.xml` because packing otherwise excludes nested `.nuspec` files.

The producer builds Classic through the compiler in its own isolated graph, using the same pinned CodeDom and MetadataLoadContext closure as the packaged SDK. Its diagnostic log retains the temporary theme assembly and MarkupCompilePass2, while BuildInputs records original XAML alongside source and generated resources. PresentationFramework.Classic adds one managed runtime DLL; PresentationUI now compiles its full original source and resources as a runtime assembly. Its Windows-only document-service contracts remain compile-only. The assembly/resource boundary is qualified separately from non-null FlowDocument text formatting and Windows document services. A new source/profile revision requires a fresh private feed and empty consumer cache even when its local package version stays unchanged.
